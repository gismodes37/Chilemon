# Zero-config companion onboarding

Objective: a non-technical user runs the installer and starts transmitting with no manual Asterisk or config editing. Branch: feat/companion-autostart-task (continuation). Delivery: work-unit commits; runner `python -m pytest tests/ -q` plus `bash -n install/*.sh` and Pi live verification.

## Specs

S1 — "la idea es que el usuario no tecnico, inicie el instalador y comience a transmitir sin mas problemas, a eso tenemos que llegar"

S2 — The main Pi installer must install the `[radio-companion]` dialplan context automatically and idempotently, using the node number entered during installation. Today `install/install_chilemon.sh` injects the `[companion-app]` IAX2 peer with `context=radio-companion` (`install/asterisk/iax-companion.conf:19`) but never creates that context; only `install/companion/install.sh:236-250` does, on the Linux-PC path. `install/asterisk/extensions-companion.conf` stays the single source of truth. Acceptance: a fresh installer run leaves `extensions.conf` with `_X!` → `rpt(<prompted node>|S)`; a second run does not duplicate the context.

S3 — A fresh Pi with a different node number must work with no hardcoded `494780`. The interactive prompt at `install/install_chilemon.sh:1116-1119` supplies `local_node`; the WebRTC env file fallback at `:950` must not become the effective value. Acceptance: static check proves the dialplan substitution uses the prompted node, and the docs no longer tell the user to edit it by hand.

S4 — Windows onboarding must be one action: place the dashboard-generated `config.toml` at `%USERPROFILE%\.chilemon\config.toml`, register logon autostart and start the companion. Assumption pending confirmation: the user obtains `config.toml` from the dashboard **Companion App** button (`public/api/companion-download.php`). Dashboard instructions at `public/views/dashboard.php:1094-1105` currently require manual download/copy/start, and `companion/build.bat` referenced in docs does not exist.

S5 — Operator docs must stop listing the dialplan context and manual config placement as normal user steps (`docs/companion.md:60,127`, `docs/companion_ES.md:60,127`).

S6 — "si por favor, dale" — authorization for T4: "Generar los secretos en el instalador y propagarlos al mismo tiempo". Acceptance: a fresh Pi install writes non-placeholder `iax_phone_pass` and `webrtc_secret` into `config/local.php`, renders the same `iax_phone_pass` into the `[webrtc-bridge]` IAX2 peer and both secrets into `/etc/default/chilemon-webrtc`, reuses existing secrets on re-run, and no longer asks the operator to edit `CHANGE_ME`/`CHANGEME_PHONE_SECRET` by hand.
